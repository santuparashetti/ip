Fix the mindset first
The fear is real. Here's why it exists and exactly how to beat it.
You are not a fraud. Using AI to fix bugs is what senior engineers do in 2025. The interview tests whether you can explain the fix, understand trade-offs, and make the decision yourself. That's it.
Why confidence drops after 10 years
The real reason you feel unsure
• You solve problems daily using tools (AI, docs, Stack Overflow)
• Interviews simulate "no tools" — feels artificial
• You haven't practiced articulating what you already know
• You compare your insides to others' outsides

None of this means you don't know the material.
What 10+ years actually gives you
✓ Pattern recognition — you've seen these bugs before
✓ Trade-off thinking — you know what breaks at scale
✓ Team + communication skills — junior devs don't have this
✓ Production instincts — you know what actually matters
✓ Context — you understand WHY, not just HOW
The CDDR answer framework (use for every question)

C — Context
    "We had a 300ms lag on our product page..."

D — Diagnosis
    "I profiled it and found excessive re-renders

D — Decision
    "I evaluated useMemo vs restructuring state.

R — Result
    "Reduced render time by 80%. Documented the
    pattern for the team."

Pre-interview ritual (the night before + morning of)
Night before: Do a 30-min light review of your weakest domain. No cramming. Then stop. Sleep matters more than last-minute studying.

Morning of: Say this aloud before you start: "I have 10 years of real production experience. I've built real things that real users use. I'm allowed to think out loud and I'm allowed to not know everything." Confidence is a habit, not a feeling you wait for.

Promise.resolve()
  .then(() => log('3'));    // microtask (2nd)
console.log('4');           // sync

// Output: 1, 4, 3, 2
this binding rules
// 1. Default: window (or undefined strict)
function f() { console.log(this); }

// 2. Implicit: object before the dot
obj.method()  → this = obj

// 3. Explicit: call/apply/bind
f.call(obj)   → this = obj

// 4. Arrow: inherits outer this
// 5. new: creates new object
Debounce implementation
function debounce(fn, delay) {
  let timer;
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => {
      fn.apply(this, args);
    }, delay);
  };
}
// Fires AFTER user stops typing
const search = debounce(api.search, 300);
Promise patterns
// All must resolve (fails fast)
await Promise.all([p1, p2, p3]);

// All settle, no failure
await Promise.allSettled([p1, p2]);

// First to resolve wins
await Promise.race([p1, p2]);

// First to resolve, not reject
await Promise.any([p1, p2]);
Deep copy approaches
// Shallow (loses nested refs):
const c = { ...obj };
const c = Object.assign({}, obj);

// Deep (loses Date, functions):
const c = JSON.parse(JSON.stringify(obj));

// Best (modern):
const c = structuredClone(obj);

// Lodash:
const c = _.cloneDeep(obj);

Sliding window template
function slidingWindow(arr, k) {
  let windowSum = 0;
  let maxSum = 0;

  // Build first window
  for (let i = 0; i < k; i++)
    windowSum += arr[i];
  maxSum = windowSum;

  // Slide the window
  for (let i = k; i < arr.length; i++) {
    windowSum += arr[i] - arr[i - k];
    maxSum = Math.max(maxSum, windowSum);
  }
  return maxSum;
}
HashMap frequency template
function freqMap(arr) {
  const map = new Map();

  for (const item of arr) {
    map.set(item, (map.get(item) || 0) + 1);
  }
  return map;
}

// Two-sum variant:
function twoSum(nums, target) {
  const seen = new Map();
  for (let i = 0; i < nums.length; i++) {
    const comp = target - nums[i];
    if (seen.has(comp))
      return [seen.get(comp), i];
    seen.set(nums[i], i);
  }
}

Reflow vs repaint
Reflow (expensive — avoids these):
  Changing width, height, margin,
  padding, font-size, position

Repaint (less expensive):
  Changing color, background,
  box-shadow, border-color

Composite only (GPU, fast ✓):
  transform: translate/scale/rotate
  opacity

Rule: animate transform + opacity only

SQL JOIN types
INNER JOIN — rows matching in BOTH tables
LEFT JOIN  — all left + matching right
             (nulls where no match)
RIGHT JOIN — all right + matching left
FULL OUTER — all rows from both tables

Example:
SELECT u.name, o.total
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE o.total > 100;
ACID properties
A — Atomicity
    All or nothing. If one step fails,
    the whole transaction rolls back.

C — Consistency
    DB goes from one valid state to another.

I — Isolation
    Concurrent transactions don't interfere.
    Levels: READ UNCOMMITTED → SERIALIZABLE

D — Durability
    Committed transactions survive crashes.
SQL vs NoSQL decision
Use SQL (PostgreSQL/MySQL) when:
  • Structured, relational data
  • Complex queries + joins
  • ACID compliance required
  • Schema is stable

Use NoSQL (MongoDB/DynamoDB) when:
  • Flexible/changing schema
  • Massive scale, simple access
  • Hierarchical/document data
  • Need horizontal sharding
Indexing rules
✓ Index columns in WHERE clauses
✓ Index columns in JOIN conditions
✓ Index columns used in ORDER BY

✗ Don't index low-cardinality cols
  (boolean, gender — not selective)
✗ Don't over-index write-heavy tables
  (every write must update all indexes)

Composite index: order matters!
  INDEX(a, b) helps WHERE a=? AND b=?
  but NOT WHERE b=? alone

Core Web Vitals targets
LCP (Largest Contentful Paint)
  Good: ≤ 2.5s  |  Poor: > 4s
  Fix: preload images, faster server

FID/INP (Interaction to Next Paint)
  Good: ≤ 200ms  |  Poor: > 500ms
  Fix: reduce JS blocking, code split

CLS (Cumulative Layout Shift)
  Good: ≤ 0.1  |  Poor: > 0.25
  Fix: set img dimensions, avoid
  injecting content above fold

SSR vs CSR vs SSG vs ISR
CSR (React default)
  ✓ Rich interactivity
  ✗ Poor SEO, slow first paint

SSR (Next.js getServerSideProps)
  ✓ SEO, fresh data, fast FCP
  ✗ Server load, no caching by default

SSG (static generation)
  ✓ Fastest, CDN cached
  ✗ Build time grows, stale data

ISR (incremental static regen)
  ✓ Static speed + fresh data
  ✓ Revalidate on schedule

✓ Only call from React functions

useEffect  — side effects, subscriptions

useCallback— memoize functions (stable ref)

When things re-render
A component re-renders when:
  • Its state changes (useState)
  • Its parent re-renders
  • Context it subscribes to changes
  • Props change

Prevent re-renders with:
  • React.memo (compare props)
  • useMemo (stable values)
  • useCallback (stable functions)
  • State colocation (lift down)
  • State splitting

✓ Think aloud — always narrate
✓ Ask clarifying questions first
✓ State your approach before coding
✓ Name your complexity (Big O)
✓ Mention edge cases
✓ Say trade-offs, not just answers
✗ Don't go silent for > 30 seconds
✗ Don't pretend you know if you don't
✗ Don't skip the "why" for any choice
Self-mock: run these yourself
⚡
JS Core Mock (20 min)
Pick 4 JS questions. Answer each aloud for 4 minutes without looking at hints. Then reveal and score yourself.
⚛️
React Mock (20 min)
Pick 3 React questions. Add a coding challenge: implement a custom hook or debounced search from scratch.
🌲
DSA Mock (30 min)
Pick one DSA problem. Write pseudocode first (5 min). Then code (20 min). State complexity (5 min). No hints allowed.
🔗
System Design Mock (30 min)
Pick a design prompt. Spend 5 min on requirements, 15 min drawing the architecture on paper, 10 min on trade-offs.
👥
Behavioral Mock (20 min)
Pick 4 behavioral questions. Answer each aloud in STAR format. Record yourself if possible — then review.
🎯
Full Mock (60 min)
Combine all: 2 JS/React questions + 1 DSA problem + 1 system design + 2 behavioral. Timer on. No breaks.
Scoring yourself
After each mock session, ask yourself:

1. Did I think aloud throughout? (yes/no)
2. Did I ask clarifying questions before jumping in? (yes/no)
3. Could I explain the "why" for every decision I made? (yes/no)
4. Did I mention trade-offs, not just answers? (yes/no)
5. Did I state time/space complexity? (yes/no)

3+/5 = good. 5/5 = ready.
